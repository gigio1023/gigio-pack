# Medium and Figures

Load this when choosing where the document lives, building the HTML or Notion version, or placing figures. Production of the figures themselves belongs to `technical-diagram`, `mermaid-diagrams`, `data-chart`, and `drawio-diagram`; this file covers what the document needs from them.

## Medium routing

| Situation | Medium | Notes |
| --- | --- | --- |
| Intermediate results, handoff to another agent | Per-topic Markdown files in a tidy directory | The author reads none of it in chat; the directory is the deliverable |
| Research or analysis read on a desktop monitor | Single-file HTML, wide | Sticky table of contents, about 1180 to 1700 px content width, chart beside text, nested bullets and tables instead of prose |
| Document-shaped page (handbook, onboarding, memo) | `notion-doc` canon HTML | 720 px, byte-identical template style block, template classes only, no inline style or raw color, page icon and meta line; run its lint before delivery |
| Page that lives in Notion | Native Notion blocks through the Notion MCP or plugin | Never browser automation for edits; screenshots for review are fine |
| Quick decision aid read once | One very concise page or Artifact | Strengths, weaknesses, features, one table; Artifacts otherwise serve as a design reference, not the destination |
| Formal external deliverable | A client-report skill | Out of scope here |
| Print | A Markdown-to-PDF pipeline where the workspace has one | Layout only; content rules unchanged |

Markdown is the source of truth; HTML is regenerated by a build script and never hand-edited. Reports that live in the repository link back to their Markdown original.

## Single-file HTML

- Fonts embedded (subset variable fonts kept the two-face set under half a megabyte); no external scripts, stylesheets, or images; figures as inline SVG.
- Renders on Windows and in Edge: encoding declared, CSS features checked, no dependence on a font the author's machine happens to have.
- Light color scheme unless the reader asked otherwise; dark mode must not break contrast when supported.
- Chart SVG uses presentation attributes with the template's tokens (`fill="var(--c-blue)"`) and a `<title>` per element for hover; wide SVG wraps in a scrolling container.
- A first pass with custom CSS before checking the canon was wasted work. Start from the template.

The wide layout is a named deviation from the canon, used for research and analysis reports the author reads on a desktop. Say so when producing it. Two reports in a row should not share a palette preset; vary within the design system. A type pairing that worked: SUIT 800 for headings with Pretendard 400 for body. Formatting tells named as slop: emoji, dashes, left-border callouts, dot badges, uppercase kickers, rows of stat tiles.

## Notion pages

- Tables span the full text width; cells hold short statements; detail collapses under toggles; dividers separate sections; header colors aid scanning.
- Nested bullets, callouts, and toggles carry structure. A page that is one wall of prose "하나도 안 읽혀".
- No tags on documents in the index table, no emoji in titles, no top-of-page metadata the reader did not ask for, no unverifiable metadata such as reading time.
- The summary sits above the metadata block, not below it.
- Figures are re-inserted when converting from HTML; a conversion that lost them made the page "너무 이상해". A figure that is too small in the narrow body is fixed inside the SVG (type size, whitespace, layout); Notion Markdown images have no width property.
- Large replacements are re-fetched and diffed afterward. Child pages and databases are preserved. Korean corruption during a publish stops the batch.
- The hub page itself is the overview; do not add a redundant overview document beside it.

## Figures inside a document

- One question per figure, one abstraction level, a numbered caption ("그림 1. 월별 처리 건수 (2026-09-01 기준)"), and the takeaway stated in the adjacent text.
- The reader's own organization appears in every comparison chart: scatter plots, price, latency, capability matrices, funding timelines, landscape tables.
- Restraint: nothing added because space remained; a diagram whose text is unreadable and whose parts sit unconnected "그럴듯해 보이지만" fails. The standard is the OpenAI and Anthropic engineering-blog diagrams. Empty space may remain empty.
- ELI5 belongs in figure blocks: one familiar analogy plus the literal system mapping under it. The whole document is not written that way.
- Replacing a figure keeps its question, relationships, and insight while re-verifying labels and data; archive the old draw.io sources rather than delete them.
- SVG, never ASCII art. Direct SVG generation with a consistent typeface replaced GUI-oriented draw.io work for new figures.
- Grey plus one accent color; no pie charts, 3D, or dual axes; small multiples over a rainbow legend; a chart earns its place by answering a question a table could not.

## Bilingual figures

Shared figures carry English labels. Translate against the project glossary and translation rules (a 129-term glossary and per-figure sheets exist in the workspace), not literally: "policy decision" versus "policy enforcement", "PII detection" versus "redaction", "benign-input false-block rate" versus "over-refusal" stay distinct; a product name is spelled as its owner spells it, never phonetically. Precise product and API names are spelled out ("OpenAI Responses API", "Anthropic Messages API"). After translation, run a numeric equivalence check between source and translated strings and adjudicate each difference; the check does not replace re-verifying the numbers themselves. Titles and labels are noun phrases; a narrated clause in a label ("운영자는 정책을 적용하고 결과를 다시 시험한다") becomes "운영자의 정책 적용과 결과 테스트".
